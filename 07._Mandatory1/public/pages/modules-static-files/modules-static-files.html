Statiske filer og express.static()

Statiske filer er filer, som browseren skal kunne hente direkte fra serveren. Det kan for eksempel være CSS filer og JavaScript-filer til frontenden. 

app.use(express.static("public"));

Denne linje gør at Express kan sende filer fra public mappen til browseren. Hvis en CSS fil ligger i public/assets/css/index.css, kan den bruges i en HTML fil med følgende sti: 

link rel="stylesheet" href="/assets/css/index.css"

Det er også for sikkerhedsmæssige årsager, da det kun er filer i public mappen som kan hentes direkte fra browseren. Serverfiler som app.js og package.json skal ikke ligge i public, fordi brugere ikke skal selvfølgelig ikke have adgang til dem.

ES modules

Man kan eksportere en funktion eller variabel fra en fil til en anden, hvis man importerer den.

Eksempel på en fil, der eksporterer en funktion: 

export function getexample(example) {
        return "Hej" + example;
        }

Funktionen kan derefter importeres i en anden fil: 

import {getExample} from "./example.js"
            console.log(getExample("eksempel på eksport/import"))

For at bruge ES Modules i Node.js skal man skrive type: "module" i package.json. Det gør det muligt at bruge import og export i projektets JavaScript-filer.

CommonJS VS ES Modules

CommonJS bruger require() og module.exports og ES Modules bruger import og export. Ifølge vores undervisning er ES Modules den nye standard.

I Node.js aktiveres ES Modules ved at skrive type: "module" i package.json.

Environment variables

Dette er værdier, som sættes uden for selve Javascript koden. I undervisningen har vi brugt dem til at bestemme, hvilken port serveren skal køre på. 

"scripts": {
        "start": "cross-env PORT=80 node app.js",
        "start-dev": "cross-env PORT=9090 nodemon app.js"
    },

Her sætter cross-env værdien PORT før node.js overhovedet starter app.js, så når man kører npm run start-dev, bliver porten sat til 9090.

const PORT = process.env.PORT
            app.listen(PORT)

Her bliver værdien hentet fra env variables.

Man kan også gemme env variables i en .env fil, men den må ikke pushes til Github og skal stå i gitignore, hvis der er andre passwords eller api nøgler.

Client side og server side redirection

redirection betyder, at brugeren bliver sendt hen til en anden URL. Ved server side, er det serveren der bestemmer, hvor clienten skal sendes hen. Ved client side er det browseren, der står for at skifte url.

Server side

app.get("/chatterroom", (req, res) => {
        res.redirect("/blablabla")    
        })

Her i dette eksempel fra undervisningen, besøger clienten først /chatterroom, men så sender severen et response tilbage, som sender browseren videre til /blablabla

Client side

Ved client side redirection er det Javascript i browseren, der ændrer på url'en. Det er ikke noget, vi har haft kodemæssigt om i undervisning, men det ser sådan her ud:

window.location.href="/blablabla"

Projektstruktur

Det giver mening at strukturere sit projekt i mapper, så det bliver nemmere for andre udviklere (og en selv) at finde rundt i. 

public/
        assets/
            css/
            images/
        components/
            header/
            footer/
        pages/

templatingEngine/
    pages.js
    templatingEngine.js

app.js/

I dette projekt ligger CSS, billeder i assets. Siderne ligger i pages, og headeren og footeren ligger i components, fordi de bruges på flere sider. app.js og templatingEngine ligger uden for public, fordi de bruges på serveren
