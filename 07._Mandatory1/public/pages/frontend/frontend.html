Hvad betyder det at fetche?

Fetch bruges af clienten til at sende http requests til serveren. Kig eventuelt i client-server modellen under express siden. Syntaksen

GET med fetch

GET request er en "default", når man bruger den indbyggede funktion fetch i Javascript. Så selvom man ikke skriver en http metode, så bliver det et get request automatisk:

fetch("/animals")
    .then((response) => response.json())
    .then((result) => {
        console.log(result)
    })

Her bliver der sendt et GET request afsted til endpointet /animals. Responset bliver lavet om til JSON.

Hvordan fungerer response og JSON?

Når fetch sender et request, får man et response tilbage. Dette er bl.a. statuskoden og den data, fetch requestet har ønsket.

Dataen bliver sendt som JSON, når man laver det om fra tekst til JSON format med response.json()

Hvad er XSS?

Det er cross-site scripting. Det er hvor nogen prøver at sende HTML eller Javascript ind på en hjemmeside, som browseren behandler som kode og kører.

Det kan ske, hvis man eksempelvis bruger .innerHTML på noget bruger input. Brugeren kan her få lov til at indsætte både HTML og javascript i koden.

Hvis man i stedet bruger .textcontent, bliver inputtet vist som tekst, og browseren prøver ikke at køre noget fra brugerens input.

Sanitizing på backend

Sanitizing betyder at man ændre tegn, som en bruger kan finde på at sende ind til ens hjemmeside. Selvom man bruger .textContent på ens hjemmeside, skal man stadig være forsigtig og ændre de tegn, som browseren kan opfatte som html. I undervisningen har vi brugt følgende til netop dette: 

export function sanitizeXSS(string) {
    return string
        .replaceAll('&', '&')
        .replaceAll('<', '<')
        .replaceAll('>', '>')
        .replaceAll('"', '"')
        .replaceAll("'", ''')
        .replaceAll('`', '`')
        .replaceAll('/', '/');
}
